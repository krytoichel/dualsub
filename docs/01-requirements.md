# Требования к проекту DualSub

Редакция 0.1 от 16.11.2026. Лабораторная работа № 2, задачи 1 и 2.
Документ описывает существующее поведение и требования к разработке в семестре.
Состояния зафиксированы по исходному коду на начало ЛР № 2. Идентификаторы FR-n,
NFR-n и US-n сохраняются при последующих изменениях документа.

## 1. О приложении

### Назначение и текущее состояние

DualSub помогает изучать английский язык при просмотре видео в оригинальной
озвучке: плеер должен одновременно показывать английские субтитры и заранее
подготовленный русский перевод. Автоматический перевод и распознавание речи
не входят в объём проекта.

На начало работы реализован только `GET /health`: ответ HTTP 200 с JSON
`{"status":"ok","service":"DualSub"}`. Приложение FastAPI запускается через
Docker Compose вместе с PostgreSQL 16, но подключения приложения к БД ещё нет.
Каталог, плеер, учётные записи, избранное, прогресс и административный интерфейс
предстоит реализовать. Ниже они описаны как целевое поведение, а не готовые функции.

### Роли

- **Гость** — просматривает и ищет видеоматериалы, создаёт учётную запись и входит в неё.
- **Зарегистрированный пользователь** — имеет возможности гостя, смотрит видео,
  настраивает субтитры, управляет избранным и прогрессом своего просмотра.
- **Администратор** — имеет возможности зарегистрированного пользователя,
  добавляет и редактирует видеоматериалы и их дорожки субтитров.
  Учётная запись с этой ролью предоставляется заранее; самостоятельное назначение
  административной роли при регистрации не допускается.

### Термины

| Термин | Значение |
|---|---|
| Видеоматериал | Запись каталога с названием, описанием, длительностью и связанным видеофайлом |
| Дорожка субтитров | Подготовленный файл WebVTT на одном языке с текстом и временными интервалами его показа |
| Двойные субтитры | Одновременный показ активных реплик английской и русской дорожек по текущему времени видео |
| Избранное | Личный список видеоматериалов зарегистрированного пользователя |
| Прогресс просмотра | Сохранённая позиция в секундах для пары «пользователь — видеоматериал» |
| Проверка состояния | HTTP-запрос к `/health`, подтверждающий ответ приложения, но не готовность БД или плеера |

## 2. Требования к функционалу и ограничения

Состояния: **уже есть**, **нужно доработать**, **нужно сделать**.
Признаки выполнения описывают условия приёмки будущей реализации.

Все NFR относятся к целевой реализации и подлежат проверке в ходе семестра;
их выполнение на этапе подготовки требований не заявляется.

| Номер | Ограничение | Способ проверки |
|---|---|---|
| NFR-1 | Основные сценарии каталога и плеера должны работать в настольных Chrome и Firefox на Windows 11 при окне 1280 × 720 без горизонтальной прокрутки страницы. | Пройти US-2, US-4 и US-5 в обоих браузерах; записать точные версии браузеров в протоколе проверки. |
| NFR-2 | При 100 записях каталога и одном активном пользователе ответы каталога и поиска должны укладываться в 2 секунды для каждого из 20 последовательных запросов после одного прогревочного запроса на локальном стенде с 2 CPU и 4 ГБ RAM, выделенными Docker. | Измерить время от отправки запроса до получения полного ответа; зафиксировать параметры стенда; передачу видео в замеры не включать. |
| NFR-3 | Пароли должны храниться только в виде стойких солёных хешей; операции с избранным и прогрессом должны разрешаться только владельцу, а изменение каталога и субтитров — только администратору. | Проверить хранение паролей; выполнить операции без входа, с двумя обычными учётными записями и администратором; убедиться в отказе без изменения чужих данных. |
| NFR-4 | Приложение должно собираться и запускаться командой `docker compose up --build -d` с Python 3.12, FastAPI и PostgreSQL 16 без локальной установки Python и PostgreSQL. | Запустить чистый клон с Docker Compose, проверить `/health` и сохранение записи приложения в БД после перезапуска контейнеров без удаления тома. |
| NFR-5 | После запуска видео или завершения перемотки обе дорожки должны соответствовать текущему времени плеера с задержкой обновления не более 200 мс. | На локальном видео с подготовленными временными метками измерить показ и скрытие реплик на 10 границах интервалов и после 5 перемоток; каждый замер должен уложиться в 200 мс. |

## 3. Пользовательские сценарии

Состояние US-1 — **уже есть**; US-2–US-10 — **нужно сделать**.
Все примеры ниже задают проверочные данные и ожидаемое поведение. Это не описание
уже загруженного в приложение каталога или созданных учётных записей.

### US-1. Проверка доступности — FR-1

**Я как гость** имею адрес запущенного приложения, открываю `/health`, получаю
подтверждение, что приложение отвечает.

- **Вход:** базовый адрес приложения, например `http://localhost:8000`; вход не требуется.
- **Действия:** отправить `GET /health`; прочитать код и тело ответа.
- **Выход:** HTTP 200 и JSON `{"status":"ok","service":"DualSub"}`; данные не изменяются.

### US-2. Каталог и поиск — FR-2

**Я как гость** имею доступ к каталогу, открываю его, ввожу часть названия и выбираю
найденный видеоматериал, получаю описание выбранного видео.

- **Вход:** записи каталога и строка поиска; учётная запись не требуется.
- **Действия:** открыть каталог; ввести запрос; выполнить поиск; открыть найденную карточку.
- **Выход:** отфильтрованный список и карточка с названием, описанием и длительностью;
  пустая строка возвращает весь каталог, отсутствие совпадений — «Ничего не найдено».

### US-3. Регистрация и вход — FR-3

**Я как гость** имею электронную почту и придуманный пароль, заполняю регистрацию,
затем вхожу по этим данным, получаю учётную запись и доступ к личным функциям.

- **Вход:** уникальная почта корректного формата, пароль длиной от 8 символов.
- **Действия:** открыть регистрацию; отправить почту и пароль; после успешной регистрации
  открыть вход; отправить те же данные.
- **Выход:** обычная учётная запись, сообщение «Регистрация завершена»; после входа —
  активный сеанс и доступ к плееру, избранному и прогрессу.
- **Конкретный пример:** почта `anna@example.com` ещё не занята, пароль `StudyVideo42`;
  после регистрации существует ровно одна обычная учётная запись с этой почтой,
  повторный вход с указанными данными успешен.
- **Неверные или неполные данные:** пустая почта — «Укажите электронную почту»;
  `anna@` — «Введите корректную электронную почту»; пароль `123` —
  «Пароль должен содержать не менее 8 символов»; занятая почта —
  «Эта электронная почта уже зарегистрирована». Во всех случаях регистрация
  не создаёт запись и сеанс. При неверной паре почта/пароль на входе выводится
  «Неверная электронная почта или пароль», сеанс не создаётся.

### US-4. Просмотр с двойными субтитрами — FR-4

**Я как зарегистрированный пользователь** имею активный сеанс и доступный
видеоматериал с двумя дорожками, открываю плеер, запускаю видео и перематываю его,
получаю видео с синхронными английскими и русскими репликами.

- **Вход:** выбранный видеоматериал, доступное видео, английская и русская дорожки WebVTT.
- **Действия:** открыть материал; запустить видео; поставить на паузу; продолжить;
  перемотать на нужную позицию.
- **Выход:** видео воспроизводится и останавливается по командам; в каждый момент
  видны реплики, для которых `начало ≤ время < конец`; после перемотки устаревшие
  реплики исчезают и выбираются реплики новой позиции.
- **Конкретный пример:** учебный материал «First meeting» длительностью 60 секунд;
  обе дорожки содержат интервал `00:00:01.000 --> 00:00:03.000`, английская —
  `Hello!`, русская — `Привет!`. При позиции 2,000 секунды и включённых дорожках
  видны обе строки; при позиции 3,000 секунды обе строки скрыты, если других реплик нет.
- **Неверные или неполные данные:** если видео недоступно, пользователь видит
  «Видео недоступно», воспроизведение не начинается. Если отсутствует или не читается
  хотя бы одна дорожка, выводится «Двойные субтитры недоступны: проверьте дорожки»;
  запуск просмотра блокируется до исправления материала, дорожки других видео
  не подставляются. Если видеоматериал не существует — «Видеоматериал не найден»,
  плеер не открывается.

### US-5. Настройка субтитров — FR-5

**Я как зарегистрированный пользователь** имею открытый плеер с двумя дорожками,
изменяю их видимость и размер текста, получаю удобное отображение субтитров.

- **Вход:** активный сеанс, открытое видео, выбранная дорожка и размер 16, 20 или 24 px.
- **Действия:** отключить русскую дорожку; включить её обратно; отключить английскую
  и включить её обратно; выбрать размер текста.
- **Выход:** меняется только выбранная видимость; выбранный размер применяется
  к обеим дорожкам; текущая позиция видео сохраняется; настройки действуют
  до закрытия страницы плеера.

### US-6. Управление избранным — FR-6

**Я как зарегистрированный пользователь** имею выбранный материал, добавляю его
в избранное, открываю личный список и удаляю запись, получаю обновлённый список.

- **Вход:** активный сеанс, существующий видеоматериал, личный список избранного.
- **Действия:** нажать «В избранное»; открыть список; повторить добавление того же
  материала; выйти и войти; проверить список; удалить материал из избранного.
- **Выход:** до удаления в списке ровно одна запись материала, в том числе после
  повторного входа; после удаления записи нет; списки других пользователей не меняются.

### US-7. Сохранение и восстановление позиции — FR-7

**Я как зарегистрированный пользователь** имею открытое видео, ставлю его на паузу,
затем возвращаюсь к нему после повторного входа, получаю сохранённую позицию.

- **Вход:** активный сеанс, видеоматериал, текущая позиция в пределах его длительности.
- **Действия:** начать просмотр; перейти на нужное время; поставить на паузу;
  дождаться подтверждения сохранения; выйти; войти; открыть тот же материал.
- **Выход:** сохранённая позиция применяется до начала воспроизведения; запись
  относится только к текущей паре «пользователь — видеоматериал»; для нового видео
  без прогресса начальная позиция равна 0.

### US-8. Управление каталогом — FR-8

**Я как администратор** имею данные видеоматериала и видеофайл, создаю карточку,
затем редактирую её, получаю доступную в каталоге запись с актуальными данными.

- **Вход:** административный сеанс, непустые название и описание, доступный MP4
  с H.264/AAC; для редактирования — существующая карточка.
- **Действия:** открыть добавление; заполнить поля и загрузить видео; сохранить;
  открыть карточку на редактирование; изменить описание; сохранить повторно.
- **Выход:** в каталоге одна новая карточка с названием, описанием и длительностью
  видео; изменение отражается в этой же карточке без создания дубликата.
  При незаполненном поле выводится «Заполните обязательные поля», запись не сохраняется.

### US-9. Загрузка и замена субтитров — FR-9

**Я как администратор** имею видеоматериал и подготовленные дорожки, загружаю их
для английского и русского языков, затем заменяю одну из них, получаю актуальные
субтитры в плеере.

- **Вход:** административный сеанс, существующий материал, выбранный язык,
  файл UTF-8 с заголовком `WEBVTT` и корректными интервалами внутри длительности видео.
- **Действия:** открыть управление дорожками; выбрать английский язык; загрузить файл;
  повторить для русского; загрузить исправленный файл для выбранного языка;
  повторно открыть плеер.
- **Выход:** у материала по одной актуальной дорожке каждого языка; при новом
  открытии плеер использует заменённый текст, другая дорожка не меняется.
- **Конкретный пример:** для «First meeting» длительностью 60 секунд уже есть
  английская дорожка с `Hello!` на интервале 1–3 секунды. Для русского языка
  загружается файл:

  ```vtt
  WEBVTT

  00:00:01.000 --> 00:00:03.000
  Привет!
  ```

  После успешной загрузки и нового открытия плеера на 2-й секунде русская строка —
  `Привет!`, английская — `Hello!`. Повторная загрузка русского файла с текстом
  `Здравствуйте!` на том же интервале заменяет только русскую строку.
- **Неверные или неполные данные:** файл не выбран — «Выберите файл субтитров»;
  язык не выбран — «Выберите язык дорожки»; нет заголовка `WEBVTT`, временная метка
  не читается, конец не позже начала или выходит за длительность видео —
  «Некорректный файл WebVTT». Загрузка отклоняется; прежняя дорожка остаётся
  доступной, при её отсутствии новая запись не создаётся.

### US-10. Выход — FR-10

**Я как зарегистрированный пользователь** имею активный сеанс, выполняю выход,
получаю завершённый сеанс с сохранением данных учётной записи.

- **Вход:** активный сеанс; в учётной записи могут быть избранное и прогресс.
- **Действия:** нажать «Выйти»; повторно открыть страницу избранного; войти заново.
- **Выход:** после выхода отображается форма входа при обращении к личным функциям;
  после нового входа прежние избранное и прогресс доступны.
